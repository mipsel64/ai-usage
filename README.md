# AI Usage

[![macOS build and test](https://github.com/mipsel64/ai-usage/actions/workflows/ci.yml/badge.svg)](https://github.com/mipsel64/ai-usage/actions/workflows/ci.yml)

AI Usage is a native macOS menu bar app for Claude Code, Codex, Z.ai GLM Coding Plan, and Kimi Code. Click the gauge to see the reported quota windows and the time until each reset. No account is connected on first launch.

## Run

Use macOS 14.4 or later with the Swift 6 toolchain. Run `bash Packaging/setup-development-signing.sh` once to create a local **AI Usage Development** code-signing certificate. This keeps the app’s trusted-application requirement stable across rebuilds. Self-signed builds have no Apple team partition, so macOS can still request Keychain approval after a rebuild. Use an Apple Development or Developer ID identity for fully stable Keychain access. The setup writes the ignored `.local.mk` file. Run `make run` to build, sign, and open `.build/AI Usage.app`. Use the app bundle, not `swift run`, for macOS notifications. You can copy the bundle to `/Applications`. Run `make test` for the offline test suite. CI uses Xcode 26.5 (17F42).

Open **Accounts…** in the menu. Enable individual providers and allow reset notifications if you want them. The app polls connected providers at launch and approximately once a minute while running. You can also refresh a provider from the menu. Failed reads do not refill quota: the menu keeps the last reading with its observation time. A missing reset date means the provider did not report one.
Click the gauge to see current quota and reset times. Use **Connect** beside a provider to start subscription sign-in directly. Claude asks you to paste the authorization code shown after browser sign-in. Codex returns through a loopback callback. Kimi uses device authorization and shows its sign-in code while the app waits. Z.ai uses browser sign-in and creates its subscription credential automatically.

You can also open **Accounts…**, select a provider, and choose its connect action. OAuth tokens and the Z.ai subscription key stay in the login Keychain. Direct OAuth reuses the providers’ CLI client configuration. Provider terms and undocumented endpoints can change. AI Usage reports endpoint failures and does not substitute estimated quota. Choose **Notifications** in the sidebar to turn on reset alerts. AI Usage checks active sources approximately once a minute while running. If a read fails, the menu keeps the last observation and its time. A missing reset date means the provider did not report one.

The menu and account controls use native Liquid Glass on macOS 26 and later. With Reduce Transparency enabled, or on earlier supported versions, the app uses bordered controls.

|---|---|---|
| Claude | Choose **Connect with Claude** and complete browser OAuth. Paste the returned `code#state` value into AI Usage. The app reads the Claude Code OAuth usage endpoint. | Open [Claude Usage](https://claude.ai/settings/usage) from the menu. Eligible accounts can confirm **Reset for free** there. |
| Codex | Choose **Connect with Codex** and complete browser OAuth. AI Usage listens on `127.0.0.1:1455` for the callback, then reads account-scoped usage directly. | Confirm redemption of one identified, free banked reset in the app. If no eligible credit ID is reported, use the [Codex usage dashboard](https://chatgpt.com/codex/settings/usage). |

### Reset notifications

The initial reading establishes a baseline. A fresh observation can show that a window advanced past its previous deadline, that quota returned to full, or that the reported number of banked reset credits increased. AI Usage sends one local notification per provider observation. A ticking countdown, failed request, or visit to a reset page does not produce a reset alert. A notification cannot identify changes that occur and disappear between observations. No background service runs after you quit.

### Security

The default build is local, ad-hoc signed with the hardened runtime. It is not notarized or App Sandbox restricted. The Codex CLI uses its own sign-in and runs with your user permissions. The app verifies its OpenAI Developer ID signature before use. The app has no automatic updater. For distribution, use a Developer ID identity (`make app SIGN_IDENTITY='Developer ID Application: …'`) and notarize the bundle separately.
Automatic quota checks never open Keychain dialogs. Manual refresh and reset redemption can request Keychain access. Local builds use the stable self-signed **AI Usage Development** identity after `bash Packaging/setup-development-signing.sh`; without it, they use an ad-hoc signature. They use the hardened runtime and are not notarized or restricted by the App Sandbox. OAuth sign-in uses PKCE and state validation where supported. Claude, Codex, and Kimi tokens stay in the local login Keychain; Codex account IDs stay with those tokens. The app uses fixed first-party HTTPS endpoints, denies redirects, and does not collect analytics. Disconnect removes the app’s saved credentials. It does not revoke the provider’s OAuth grant or subscription key. Use the provider console to revoke access. Preferences contain connection choices and the last normalized quota observation, not tokens or raw responses. Claude and Kimi identity is kept in memory, Codex identity is decoded from its Keychain-held OAuth token, and Z.ai’s sanitised sign-in identity is stored in app preferences; disconnect removes all saved identity state. Rebuilding with a different signing identity may require new Keychain approval. The app has no automatic updater.

[AGENT.md](AGENT.md) describes how to register a new `QuotaProvider` without changing the menu, polling, or notifications. Adapters are compiled into the app; it does not load external plug-ins.
