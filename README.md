# AI Usage

[![macOS build and test](https://github.com/mipsel64/ai-usage/actions/workflows/ci.yml/badge.svg)](https://github.com/mipsel64/ai-usage/actions/workflows/ci.yml)

AI Usage is a native macOS menu bar app for Claude Code, Codex, Z.ai GLM Coding Plan, and Kimi Code. Click the gauge to see the reported quota windows and the time until each reset. No account is connected on first launch.

## Run

Use macOS 14.4 or later with the Swift 6 toolchain. Optionally, run `bash Packaging/setup-development-signing.sh` once. It creates a local **AI Usage Development** code-signing certificate in the login Keychain, so that rebuilds keep the same signing identity, and writes the ignored `.local.mk` file. Without it, builds use an ad-hoc signature. Run `make run` to build, sign, and open `.build/AI Usage.app`. Use the app bundle, not `swift run`, for macOS notifications. You can copy the bundle to `/Applications`. Run `make test` for the offline test suite. CI uses Xcode 26.5 (17F42).

Open **Accounts…** in the menu. Enable individual providers and allow notifications if you want them. The app polls connected providers at launch and approximately once a minute while running. You can also refresh a provider from the menu. Failed reads do not refill quota: the menu keeps the last reading with its observation time. A missing reset date means the provider did not report one.
Click the gauge to see current quota and reset times. Use **Connect** beside a provider to start subscription sign-in directly. Claude asks you to paste the authorization code shown after browser sign-in. Codex returns through a loopback callback. Kimi uses device authorization and shows its sign-in code while the app waits. Z.ai uses browser sign-in and creates its subscription credential automatically.

You can also open **Accounts…**, select a provider, and choose its connect action. OAuth tokens and the Z.ai subscription key are stored in private files under `~/.config/aiusage`. Direct OAuth reuses the providers’ CLI client configuration. Provider terms and undocumented endpoints can change. AI Usage reports endpoint failures and does not substitute estimated quota. Choose **Notifications** in the sidebar to turn on alerts. AI Usage checks active sources approximately once a minute while running. If a read fails, the menu keeps the last observation and its time. A missing reset date means the provider did not report one.

The menu and account controls use native Liquid Glass on macOS 26 and later. With Reduce Transparency enabled, or on earlier supported versions, the app uses bordered controls.

### Notifications

The initial reading establishes a baseline. A fresh observation can show that a window advanced past its previous deadline, that quota returned to full, or that the reported number of banked reset credits increased. AI Usage sends one local notification per provider observation. A ticking countdown, failed request, or visit to a reset page does not produce a reset alert. A notification cannot identify changes that occur and disappear between observations. No background service runs after you quit.

Low-quota alerts name each window that goes below 20% or 10% remaining, once per downward crossing. The first reading after you connect is the baseline, and after a relaunch the reading saved before the app quit is the baseline. A window that rises above a threshold and falls below it again alerts again.

### Sign-in renewal

AI Usage renews an OAuth sign-in (Claude, Codex, Kimi) when the access token expires in 5 minutes or less, and once after the provider rejects an access token. After such a forced renewal, the app makes no second one for that provider for 5 minutes unless you refresh that provider from the menu; a rejected access token in that time shows **Sign-in required**. Only one renewal runs at a time for each provider. Token requests wait up to 30 seconds; quota reads keep their shorter limit. The app keeps the new tokens in memory first and then saves them. If the save fails, the app continues with the tokens in memory, tries the save again at each later check, and shows a message on the provider card. If the provider refuses the refresh token permanently, the card shows **Sign-in required**, and automatic attempts stop until you refresh that provider from the menu or sign in again. If a renewal fails for a temporary reason while the access token is still valid, the quota check runs with that token; in all temporary cases the app tries the renewal again at the next check.

Some limits are outside the app. Claude ends a sign-in about 30 days after you sign in; renewal does not extend it. Users report this; Anthropic does not document it, and no official Claude source exists for these renewal rules. Codex and Kimi refresh tokens are reported to expire after about 30 days without use. Renewal runs only while the app runs. Z.ai uses a durable subscription key that needs no renewal; if Z.ai rejects the key, the card shows **Sign-in required**.

### Security

The default build is local, ad-hoc signed with the hardened runtime. It is not notarized or App Sandbox restricted. The Codex CLI uses its own sign-in and runs with your user permissions. The app verifies its OpenAI Developer ID signature before use. The app has no automatic updater. For distribution, use a Developer ID identity (`make app SIGN_IDENTITY='Developer ID Application: …'`) and notarize the bundle separately.
Local builds use the stable self-signed **AI Usage Development** identity after `bash Packaging/setup-development-signing.sh`; without it, they use an ad-hoc signature. They use the hardened runtime and are not notarized or restricted by the App Sandbox. OAuth sign-in uses PKCE and state validation where supported. AI Usage keeps each credential in one file, `~/.config/aiusage/<provider id>`, with mode 0600. Each save writes a temporary file, flushes it to disk, and then renames it over the credential file. The app creates the directory with mode 0700, refuses it if it is a symlink or is not owned by your user, and resets group or other permissions on it to 0700. When the app creates the directory, it tries to exclude it from Time Machine backups and to add a `.gitignore` file that contains `*`, so that a `~/.config` kept in a dotfiles Git repository does not commit the credentials. Codex account IDs stay with the Codex tokens. Each process that runs as your macOS user can read these files without a dialog. The app refuses a credential file that is a symlink, is not a regular file, is not owned by your user, is readable by group or others, or is larger than 64 KiB. If you delete the file of an OAuth provider while the app runs, the app does not write it back (unless it still retries a failed save); it uses the tokens in memory until the next renewal, and then the card shows **Sign-in required**. A Z.ai key stays in memory until the app quits. A credential that an earlier version kept in the login Keychain moves to its file at the first read, and the app then deletes the Keychain item. If you connect or disconnect while that move waits for a Keychain dialog, the move does not overwrite the newer state. If macOS refuses that read in the background, the provider card asks you to refresh that provider from the menu; this can show one Keychain dialog. Automatic checks open the Keychain only when a credential file is missing, and then do not allow a dialog. The app uses fixed first-party HTTPS endpoints, denies redirects, and does not collect analytics. Disconnect first deletes the old Keychain item and then the credential file; if the Keychain delete fails, the disconnect fails with a message and nothing changes. Disconnect does not revoke the provider’s OAuth grant or subscription key. Use the provider console to revoke access. Preferences contain connection choices and the last normalized quota observation, not tokens or raw responses. Account details stay in memory for the current session only; Z.ai reports them only at sign-in, so after a relaunch its details show again only after a reconnect, and disconnect removes them. The app has no automatic updater.

[AGENT.md](AGENT.md) describes how to register a new `QuotaProvider` without changing the menu, polling, or notifications. Adapters are compiled into the app; it does not load external plug-ins.
